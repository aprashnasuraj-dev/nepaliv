# ADR-0001 — Native desktop and provider-neutral song document

Status: Accepted for prototype, 2026-10-12.

## Decision
Use .NET 8 WPF as the Windows front-end and a strongly-typed SongDocument as the sole export boundary. Keep v1 untouched. First milestone implements local symbolic sketches without pretending speech is professional singing.

## Why
WPF has mature Windows desktop input, OpenType/Devanagari handling, low startup complexity, and easy SDK publishing. WinUI 3 is viable but raises packaging/SDK complexity; Avalonia offers cross-platform reach that is not a stated release requirement.

## Boundaries
Later split the domain, app services, provider adapters and WPF host into distinct assemblies once their contracts stabilize. Avoid taking a dependency on a hosted service, Redis, an unlicensed checkpoint, or user-uploaded imitation vocals for startup.

## Consequences
No native macOS/Linux build; the initial single-project layout is a **deliberate short-lived** simplicity choice. MIDI tests, cancellation, immutable editing, saved project loading and provider contracts are next; ship no 'v2.0 quality' claim until sung audio and native listening evaluation exist.
